# Paper test: 1-hour live smoke run (2026-11-27)

The full system ran against live Binance data: the engine (`flowlevels paper-run`) and the
dashboard (`flowlevels web`, on a smoke port bound to 127.0.0.1). It used an isolated data dir,
`data/paper/smoke/` (D-047). Nothing from this run goes into the official ledger. No orders, no
API keys. Hold-out runs: 0.

## Final run (61.5 min, 61 loops)

Data lag is measured per symbol: wall clock minus the close of the last closed minute. There
were 242 samples, one every 15 s, from `/api/health`.

| metric | value |
|---|---|
| engine status | `running` in 242 / 242 samples |
| lag median / p95 / max | 39 s / 66 s / 71 s (one sample > 70 s, 0.3 %) |
| lag before the fix (run 1) | up to ~120 s |
| compute per symbol per minute | 310–400 ms (about 2 s per minute for 6 symbols) |
| engine RSS | 186–190 MB (median 189 MB; the first run, with 1,322 backfilled minutes, peaked at 233 MB) |
| engine CPU | 4 % of one core averaged over the run (`ps`) |
| web RSS | ~95 MB |
| disk | 45 % for the whole run (`data/paper/smoke` 5 MB) |
| events | 3 × `engine_start` and 3 × `engine_stop` (info); no `poll_error`, `stall`, `divergence` or `disk` events |
| signals / trades | 0 / 0 in the hour. This is expected: windows A+B cover about 61 weeks, and the backtest has a 3.6, b 3.5, c 10.3, d 2.4 trades per week across all six symbols. |
| notifications | 6 queued as `disabled` (engine start/stop). The Telegram token is not set in `.env`, so live Telegram delivery is **not tested yet**. Run `flowlevels telegram-test` after adding it. |

The systemd caps leave plenty of headroom: engine `MemoryMax=1200M`, about 5× the measured
peak; web `MemoryMax=400M`, about 4×. They stay as they are.

## What was not covered

- **Telegram delivery.** The token and chat id are not configured yet.
- **The systemd units under systemd itself.** There is no user bus and no sudo here. The unit
  files pass `systemd-analyze verify`.
- **A live entry or exit.** No setup formed in the hour. The trade path is covered by the
  unit tests and by the DEMO replay: window B through the engine gives 153 / 153 trades equal
  to the reference run.

Raw engine logs and sampler logs stayed in a scratch directory and are not committed.
